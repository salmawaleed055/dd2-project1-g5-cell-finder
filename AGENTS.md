# Instructions for the AI assistant

Written before any implementation code, as required by Overview Section 4.1.

## The project
DD2 Project 1, Option 2: Finding Cells Worth Adding (CSCE 3304 Digital Design II - Fall 2026).
The project builds an automated EDA tool that synthesizes digital designs to And-Inverter Graphs (AIGs), enumerates small repeated Boolean logic functions (up to 4-input cuts) across standard benchmarks, classifies them into permutation-equivalent and NPN equivalence classes, filters out functions already provided by or contained in the SkyWater 130nm High-Density (`sky130_fd_sc_hd`) standard-cell library, costs and estimates the physical area of candidate cells, generates standard Liberty (`.lib`) descriptions, and quantitatively evaluates area savings when remapping designs using Yosys and ABC.
The tool is implemented in Python 3, using Yosys (with bundled ABC / `yosys-abc`) for synthesis and technology mapping, and Icarus Verilog for RTL/gate simulation.

## How this project is checked
Verification is strictly deterministic and automated through the following Make targets:
- `make check`: Verifies tool installations (Yosys, Icarus Verilog, Python 3) and validates availability of the SKY130 PDK and input libraries (`hd_reduced.lib`, `hd_usable.lib`).
- `make test`: Runs the complete regression test suite:
  1. AIG parser and graph structure sanity checks.
  2. Cut enumeration validity test and exhaustive truth table simulation across all $2^k$ input combinations for every enumerated cut.
  3. Redundancy checker self-test validating that 100% of combinational HD cells are recognized as `Exists`, and reproducing the exact reference counts of Table 4 across the 3,904 four-input non-degenerate P-classes.
  4. Broken-case verification: runs tests in `tests/broken/` and confirms they fail as expected (wrong cut truth table detected, fake HD cell flagged, malformed Liberty rejected).
- `make all`: Runs the complete Milestone 1 flow end-to-end:
  1. Synthesizes and extracts AIGs for all 6 required benchmark designs (`cpu8`, `dsp8`, `arlet6502`, `uart_apb`, `risc8`, `fir10`).
  2. Restructures AIGs using ABC (`+strash;dch`) and generates comparison statistics.
  3. Enumerates and verifies 4-input cuts on all required designs.
  4. Reproduces Table 1 baseline mapping results across both Script A (`amap`) and Script B (`&nf`) on usable and reduced libraries.
  5. Computes the comprehensive class table of HD combinational logic.
  6. Runs the Table 4 redundancy classification self-test and outputs all result summaries.

## Rules the assistant follows (overview, section 4.3)
1. Pass or fail comes exclusively from check scripts and tool executions, never from a model's subjective opinion.
2. Every number in reports, tables, and documentation originates from an output file generated by the flow.
3. Every verification check must be accompanied by a deliberately broken case in `tests/broken/` that fails when run against the checker.
4. The assistant must never modify the check scripts, test validation criteria, broken cases, or the PDK to make a failing test pass.
5. All implementations must be modular, thoroughly commented, mathematically rigorous, and adhere to sound EDA algorithms.

## What the assistant must never do
- Never weaken a check or test threshold to force a passing result.
- Never commit the PDK, raw build trees, temporary files, or any binary/intermediate file over 50 MB.
- Never move or alter Git release tags (`cp1`, `cp2`, `final`).
- Never fabricate synthesis numbers, areas, cell counts, or truth table mappings.

## Conventions
- Code style: Clean, PEP 8-compliant Python 3 with type hints and docstrings.
- Directory organization:
  - `src/`: Modular tool implementation and step runners.
  - `tests/`: Automated unit and integration tests.
  - `tests/broken/`: Deliberately broken test cases.
  - `results/`: Output tables, CSV files, logs, and generated metrics.
  - `libs/`: Generated Liberty files.
  - `ai/`: AI use and mistake logs.
  - `report/`: Technical and AI reports.
- Git commit convention: Every AI-assisted commit must carry the trailer:
  `AI-assisted: <tool>/<model>`
