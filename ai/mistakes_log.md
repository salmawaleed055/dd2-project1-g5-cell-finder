| ID | Log entry | What was wrong | How you caught it | Would a weaker check have missed it? |

| M-01 | L-003 | In `src/extract_aigs.py`, the initial ABC restructuring script ran `strash; dch; write_aiger`. Because ABC's `dch` command retains SAT-sweeping structural choice nodes inside the AIG data structure for downstream mappers, exporting directly after `dch` wrote all choice alternatives into the AIGER file (`1,702` AND nodes on `cpu8` vs `932` original, an apparent 82.6% increase instead of a reduction). | Inspected `results/aig_stats.md` after Step 1 and noticed AND node counts increased after `dch` on multiple designs. Running a second `strash` pass (`strash; dch; strash`) collapsed the choice classes to their canonical representatives, reducing `cpu8` from `932` down to `849` AND nodes (-8.91%). | Yes: `yosys-abc` and `aigtoaig` exited with return code 0 and produced syntactically valid `.aig`/`.aag` files; a check that only verified tool exit codes or file existence would have missed the uncollapsed choice nodes. |
| M-02 | L-004 | In `src/cut_enumerator.py`, `CutEnumerator.enumerate_cuts()` sorted non-dominated cuts by size (`2..4`), appended the trivial 1-input cut `Cut(var, (var,), 0xAAAA)` at the *end* of the list, and then sliced `non_dominated[:self.max_cuts_per_node]`. Whenever an internal AND node had $\ge 20$ non-dominated cuts (which occurred on `risc8`), slicing dropped the trivial cut at the tail of the list, preventing downstream fanout gates from treating that node as a cut leaf and losing 16 valid cuts on `risc8`. | Compared enumerated cut counts with and without `max_cuts_per_node` pruning across all 6 designs (`42,963` vs `42,979` cuts on `risc8`) and traced why specific 2-input cuts were missing in the fanout cone. Placed `[Cut(var, (var,), 0xAAAA)]` at index 0 and removed artificial pruning for $K=4$. | Yes: `verify_cut()` still passed 100% on the surviving cuts because every remaining cut had a valid truth table; a check that only simulated emitted cuts without checking trivial-cut retention and cut completeness would have missed the dropped cuts. |
| M-03 | L-007 | In `src/hd_classes.py`, the AI estimated CMOS transistor counts for HD cells using `is_inverting = fn_expr.strip().startswith("!")` and `2*k + (2 if not is_inverting and k > 1 else 0)`. In `sky130_fd_sc_hd`, Liberty expresses inverting gates in De Morgan form (`nand2` as `(!A) \| (!B)`, `nor2` as `(!A&!B)`, `a21oi` as `(!A1&!B1) \| (!A2&!B1)`), which start with `(` rather than `!`. Consequently, `.startswith("!")` was `False` for every inverting gate except `inv`, adding a phantom 2-transistor output inverter to all NAND/NOR/AOI/OAI gates (`nand2` = 6 tx instead of 4, `nand4` = 10 tx instead of 8) while reporting `buf` (`k=1`) as 2 transistors instead of 4. | Audited `results/hd_classes.md` against CMOS design fundamentals (`inv_1` = 2 tx, `buf_1` = 4 tx, `nand2_1`/`nor2_1` = 4 tx, `and2_1`/`or2_1` = 6 tx) and cell widths in `0.46 um` sites. Replaced the string prefix heuristic with `compute_hd_family_cmos_cost()`. | Yes: `hd_classes.py` ran without errors and produced a well-formatted 83-row markdown/CSV table; a check that only verified table generation or column formatting without checking physical transistor counts of reference gates (`nand2`, `buf`) would have missed it. |
| M-04 | L-008 | In `src/redundancy.py`, the initial DP for Table 4 stored a single tuple `(total_lit, nmos, pmos)` per truth table using Python lexicographical `<` comparison, which preferred `(6, 2, 4)` over `(6, 3, 3)` on `0x013F` (`!((A\|B\|C)&(D\|(B&C)))`) because `2 < 3` in the NMOS field even though `pmos = 4 > 3`. It also omitted the $\le 3$ series transistor rule of Section 4 Step 4 when counting read-once 4-input cells (getting 10 including `nand4`/`nor4` instead of 8), and then used a hardcoded list and a hardcoded `0x017F` (a 14-transistor gate) to make the counts equal 5 and 8. | Reviewed the synthesized expressions and transistor counts of all 9 single-stage `New` classes and all read-once 4-input trees by hand against Section 4 Step 4 ("at most 3 in series in any stage"). Rewrote `synthesize_one_stage_4inp()` to track Pareto-optimal series stacks and enforce `nmos <= 3 and pmos <= 3`. | Yes: unit assertions that only checked `counts["..."] == 5` and `counts["..."] == 8` passed when the hardcoded hex constants were present; only inspecting the synthesized expressions, transistor counts (`14` vs `12`), and series depths caught the error. |
| M-05 | L-007 | `eval_lib_expr()` in `src/redundancy.py` only accepted variable names in `var_map` and boolean operators, raising `ValueError: Unknown token '0'` on constant-function cells (`macro_sparecell`, `conb_1`), and `test_redundancy.py` only tested the 4-input subset of `hd_usable.lib` rather than all 264 single-output combinational cells (1 to 6 inputs).
